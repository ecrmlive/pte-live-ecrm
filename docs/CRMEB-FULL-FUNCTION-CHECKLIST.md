# CRMEB MER v4.0 全端功能验收总清单

本文件是**开发与验收入口**，用于逐端、逐页面、逐按钮确认七禧是否完成 CRMEB MER v4.0 功能对齐。

正式交付系统为：**PC 用户端、小程序&H5 用户端、统一后台管理系统、店铺管理系统**。统一后台管理系统内按权限呈现平台、商户、区域、客服、运营五种角色菜单；店铺管理系统独立。店员、配送、服务人员属于店铺系统角色，不得作为独立交付系统或新增独立入口。

> “功能点已列出”不等于“功能已完成”。任何功能只有同时满足本文件的完成条件，才能标记为完成。

## 2. 按端模块目录

### 平台管理后台 / 区域管理后台

1. 首页与数据大屏：商品、订单、用户统计和控制台。
2. 店铺与区域：商户入驻、商户列表/管理员/设置、店铺分类/分组/类型、区域代理/人员/审核/设置。
3. 商品：分类、品牌、参数、标签、保障服务、商品审核、评论、活动标签和价格说明。
4. 订单与售后：订单列表、核销记录、退款监管、发票、物流与导出。
5. 用户与会员：用户、分组、标签、等级、付费会员、反馈、搜索记录、协议与用户设置。
6. 营销：平台券/商户券、秒杀、拼团、预售、助力、积分、直播、充值、报名、专场和营销素材。
7. 分销：分销员、等级、订单、说明、海报、特权、礼包、配置和提现银行。
8. 财务：平台资金流水、用户提现/充值、店铺结算、分账、转账、商圈代理结算和发票。
9. 内容：文章、公告、社区内容/分类/话题/评论、素材库与内容配置。
10. 装修：页面装修、微页面、页面分类/链接、素材、主题、个人中心、店铺街、商品详情、系统表单。
11. 客服：客服列表、自动回复、客服设置。
12. 应用：公众号、微信菜单/模板消息/自动回复、小程序配置/订阅消息/下载、APP 配置/升级。
13. 设置与权限：管理员、角色、菜单、商城/支付/配送/存储/接口/短信配置、公告与消息。
14. 维护：日志、导出记录、缓存、备份、授权、开发配置和组合数据。

### 商户管理后台 / 店铺后台

1. 首页：商品、订单和经营统计。
2. 商品：商品、分类、规格、参数、标签、单位、卡密、服务模板。
3. 订单：订单管理、评价、退款、核销、预约服务与代客下单。
4. 营销：优惠券、秒杀、拼团、预售、助力、积分、直播、社区、专场和优惠套餐。
5. 财务：余额、账单、资金流水、提现、发票、收款、分账、转账和分账商户申请。
6. 员工与客服工作台：管理员、身份/角色、店员、配送员、服务人员、自动回复、岗位统计、会话、订单辅助和服务统计。
7. 履约：物流公司、运费模板、同城配送、发货点、打印与小票。
8. 装修：店铺装修、素材、商品分类、系统表单与店铺展示配置。
9. 店铺设置：店铺资料、配置、付费会员、开放账户、一号通与操作日志。

### 小程序 / H5 / PC 用户端

1. 认证与账户：注册登录、验证码、手机号、密码、账号注销、用户资料。
2. 首页与内容：DIY 首页、导航、公告、协议、搜索、分类、推荐、品牌与店铺街。
3. 商品与店铺：商品列表/详情/SKU、评价、收藏、店铺主页、店铺商品、直播挂货。
4. 购物车与交易：购物车、地址、订单核对、多商户拆单、支付、取消、订单详情、物流、发票与评价。
5. 售后：申请退款/退货、寄回、平台介入、售后详情与状态查询。
6. 营销：优惠券、秒杀、拼团、预售、助力、积分商城、会员、充值和新人权益。
7. 增长：分销绑定、推广关系、佣金、提现、海报与积分。
8. 内容互动：社区列表/详情/评论/发帖/我的发布、直播间、预约服务。
9. 客服：商户客服会话、订单辅助、共享 pte-live-im SDK 通信。

## 3. 每一项的完成条件

对 `features-master.tsv` 的每一行逐项核对，满足以下全部条件才可标记“完成”：

1. **页面/入口**：对应端可进入真实页面，后台动态菜单不得落入 `ecrm/placeholder/index.vue`。
2. **交互**：筛选、列表、分页、空状态、详情、表单、取消、二次确认、成功反馈与 CRMEB 对应操作一致。
3. **接口**：调用真实 Go API；禁止 mock、空数据、前端假成功或仅菜单占位。
4. **权限与隔离**：前端隐藏与服务端鉴权同时生效；商户/店铺/店员必须验证 `mer_id`，区域账号必须验证 `region_ids`。
5. **状态机**：订单、支付、退款、库存、优惠、积分、佣金、结算按 [FUNCTIONAL-TRUTH.md](./api/FUNCTIONAL-TRUTH.md) 验收幂等与状态转换。
6. **UI 对照**：以相同角色、路径、数据状态截图，对照 CRMEB 的布局、字段、筛选、按钮、弹窗与反馈。
7. **验证证据**：记录接口结果、权限拒绝结果、关键链路测试和截图路径；没有证据不得标完成。

## 4. 当前实现状态的唯一口径

- 功能**基线范围**：以本文件第 1 节、`docs/features/` 和 `features-master.tsv` 为准。
- 后台**实际完成度**：以 [crmeb-vben-parity.md](./crmeb-vben-parity.md) 为准。
- 当前存在动态菜单 placeholder 回退，且区域、商户/店铺内部工作台和 PC 都未完成全量验收；因此当前整体状态是：**未完成，不能宣称 100% 对齐或生产级。**

## 5. 推荐逐项关闭顺序

1. 平台/区域：商户、商品、订单、售后、财务、营销、内容、系统设置、区域结算。
2. 商户/店铺：商品、订单、售后、优惠券/活动、员工、财务、配送、装修、店铺设置。
3. 用户端：登录、商品、购物车、普通订单支付、售后、优惠券、会员/分销、直播/社区/预约、客服。
4. 商户/店铺内部工作台：岗位菜单、核销配送、售后、会话和订单辅助。
5. PC：复用 C 端业务接口逐项核对页面、交互和响应式布局。

每完成一项，在对应功能文档或验收记录中补充：`实现文件`、`API`、`权限`、`测试证据`、`CRMEB 对照截图`。没有这五项，不得标记完成。
