# 统一后台功能总索引与 100% 闭环规则

本索引覆盖同一套 `admin-platform` Vben 应用中的平台、商户、区域、运营、客服五种角色。它不把五种角色拆成五个前端项目。

## 唯一逐项清单

完整功能不是手工摘要，而是 [`docs/generated/features-master.tsv`](../generated/features-master.tsv) 中 `portal=平台后台` 的 **1333** 行，以及 `portal=客服端` 的 **18** 行。每一行给出模块、页面、按钮/接口、CRUD 类型、CRMEB 来源和标识符；该文件是开发、测试和验收的唯一逐项口径。

逐页、逐按钮可读清单见 [`docs/features/01-platform-admin.md`](../features/01-platform-admin.md)，客服 API 清单见 [`docs/features/05-customer-service.md`](../features/05-customer-service.md)。

## 客服 18 项接口范围

验证码、配置、登录/扫码/退出、商户信息、聊天用户列表、用户备注、聊天记录、用户资料、图片上传、订单/订单状态/物流、退款/退款物流、商品信息。实际消息、UserSig 与会话正文仍由 `pte-live-im` 管理，七禧只处理后台授权与业务辅助。

## 五角色数据范围

| 角色 | 角色代码 | 服务端范围 |
| --- | --- | --- |
| 平台 | `platform` | 全平台 |
| 商户监管 | `merchant` | `merchant_ids` |
| 区域 | `region` | `region_ids` 及范围内商户 |
| 运营 | `operations` | 授权运营配置和内容范围 |
| 客服 | `customer_service` | 授权店铺会话队列 |

## 单项关闭条件

每个操作必须同时关联：Vben 页面/入口、真实 Go API、服务端角色和按钮权限、数据范围拒绝测试、中文模拟数据、状态机或回归测试、同状态截图。任一缺失即为“进行中”。

当前实现证据见 [`ADMIN-PLATFORM-ROLE-ACCEPTANCE.md`](./ADMIN-PLATFORM-ROLE-ACCEPTANCE.md)；该台账尚未标记全量完成。
