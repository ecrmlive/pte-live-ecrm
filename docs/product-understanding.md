# 我们要做什么（产品与业务全景）

本文回答：**qixi-live-mergers 要建成什么**。功能基线对齐 CRMEB 多商户 MER v4.0；实现栈为 Go + Vben + uni-app x；表前缀统一 `qixi_`。

验收级功能点见 [`features/README.md`](./features/README.md)。  
表结构见 [`schema/README.md`](./schema/README.md)。

---

## 1. 一句话

做一个**多商户入驻式商城平台**：平台运营审核与规则，商户经营商品与履约，用户完成购买与售后；资金在用户、商户、平台之间可追溯结算。

---

## 2. 角色与端（必须同时理解）

| 角色 | 端 | 核心事 |
| --- | --- | --- |
| 平台运营 | 平台后台 | 审商户、管类目品牌、监管商品/订单、营销规则、财务提现审核、RBAC、DIY |
| 商户 | 商户后台 + 商户手机端 | 本店商品/SKU/库存、接单发货/核销、店铺营销、提现、店员客服 |
| C 端用户 | 小程序/H5/App（及 PC） | 浏览、加购、多店结算、支付、售后、分销/积分/会员、客服 |
| 客服 | 客服工作台 | 会话、查单、备注用户 |
| 店员/配送/服务人员 | 移动工作台 | 核销、配送、预约服务工单 |

数据隔离铁律：商户域一切读写带 `mer_id`；平台可跨店；用户只看自己的资产与订单。

---

## 3. 核心业务对象（对应 `qixi_*` 表）

| 对象 | 主表 | 要点 |
| --- | --- | --- |
| 商户 | `qixi_merchant` | 入驻、开关店、保证金、余额、分账商户号、配送方式 |
| 入驻申请 | `qixi_merchant_intention` | 用户申请 → 审核 → 开通商户 |
| 商品 SPU | `qixi_store_product` | `mer_id`；平台审核 `status`；商户上下架 `is_show` |
| SKU | `qixi_store_product_attr_value` | 价格/库存/条码/佣金/会员价 |
| 购物车 | `qixi_store_cart` | 按商户分堆；支持立即购买 |
| 支付主单 | `qixi_store_group_order` | 一次支付可含多商户；平台券/积分在此层 |
| 商户子单 | `qixi_store_order` | 履约、发货、核销、佣金、平台手续费 |
| 子单商品 | `qixi_store_order_product` | 行级优惠、退款数量、活动类型 |
| 售后 | `qixi_store_refund_order` | 仅退款/退货退款状态机 |
| 用户 | `qixi_user` | 余额、积分、佣金、分销关系、付费会员 |
| 账单 | `qixi_user_bill` | 余额/积分等流水 |
| 商户提现 | `qixi_financial` | 提现申请与审核 |
| 分账 | `qixi_store_order_profitsharing` | 支付后平台/商户分账 |
| 优惠券 | `qixi_store_coupon*` | 店铺券/商品券/平台券 |

## 4. 主链路（必须能默写）

### 4.1 商户入驻

```text
用户提交入驻(qixi_merchant_intention)
  → 平台审核通过/拒绝
  → 通过则创建商户(qixi_merchant) + 商户管理员
  → 商户完善资料、保证金（若开启）、开店
```

### 4.2 商品上架

```text
商户创建商品(SPU+SKU+运费模板)
  → 若商户需审: 平台审核 status
  → 商户上架 is_show
  → C 端可见可售
```

商品形态（字段语义，实现时保持）：

| 字段 | 含义 |
| --- | --- |
| `type` | 0 实体 / 1 虚拟 / 2 网盘 / 3 卡密 |
| `product_type` | 0 普通 / 1 秒杀 / 2 预售 / 3 助力 / 4 拼团 |
| `delivery_way` | 自提 / 快递 / 包邮等 |
| `spec_type` | 单规格 / 多规格 |

### 4.3 下单与支付（多商户）

```text
加购(qixi_store_cart，按 mer_id 分堆)
  → 结算计价（商品+运费-店铺券-平台券-积分-会员价）
  → 创建 group_order（支付主单）
  → 按商户拆 store_order（履约子单）+ order_product
  → 扣库存（活动库存规则）
  → 调起支付（余额/微信/支付宝等）
  → 支付回调: paid=1，写 pay_time，推履约
  → 分账/记账（profitsharing、financial_record、user_bill）
```

订单状态（子单 `status`，在 `paid=1` 后）：

| status | 含义 |
| --- | ---: |
| 0 | 待发货 |
| 1 | 待收货 |
| 2 | 待评价 |
| 3 | 已完成 |
| 9 | 拼团中 |
| 10 | 待付尾款（预售） |
| 11 | 尾款超时 |
| 20 | 预约服务中（已打卡/待核销） |
| -1 | 已退款 |
| is_del=1 | 用户取消（未支付场景） |

发货类型：快递 / 送货 / 虚拟 / 电子面单 / 同城 / 卡密自动 / 自提核销 / 商家寄件。

### 4.4 售后

```text
用户申请退款/退货(qixi_store_refund_order)
  → 商户审核（可平台介入）
  → 退货物流（若退货）
  → 退款到原路/余额
  → 回滚库存、佣金、积分、优惠占用
  → 更新订单/行退款状态
```

售后状态：`0 待审 → -1 拒绝 | 1 待退货 → 2 待收货 → 3 已退款`。

### 4.5 商户结算与提现

```text
订单完成/可结算
  → 商户余额 mer_money 增加（扣平台佣金 commission_rate）
  → 商户发起提现(qixi_financial)
  → 平台审核 → 打款 → 回凭证
```

分账表 `qixi_store_order_profitsharing` 记录支付侧分账（收付通/服务商）。

### 4.6 分销与积分（增长）

```text
用户绑定推广关系(spread_uid)
  → 下单产生一级/二级佣金(extension_*)
  → 佣金入 brokerage_price / 提现
积分：下单抵扣、完成赠送、积分商城兑换；流水进 user_bill
```

## 5. 营销能力清单（业务上要覆盖）

| 能力 | 关键表/类型 | 说明 |
| --- | --- | --- |
| 优惠券 | `qixi_store_coupon*` | 店铺/商品/平台通用/品类/跨店 |
| 秒杀 | product_type=1 + seckill 表 | 场次、限量 |
| 预售 | product_type=2 | 全款/定金尾款 |
| 助力 | product_type=3 | 邀人砍价 |
| 拼团 | product_type=4 | 成团/失败 |
| 满减折扣 | store_discounts* | 店铺活动 |
| 积分商城 | 积分商品 type | 兑换 |
| 直播 | broadcast_* | 直播间带货 |
| 会员 SVIP | user.is_svip | 会员价 |
| DIY 装修 | diy / page_* | 首页与微页面 |

首期建议仍按 `features` 的 P0→P1→P2，但**表与领域认知要一次性吃透**，避免后期拆单/分账返工。
