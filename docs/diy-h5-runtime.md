# H5 / 小程序 DIY 装修运行链路

## 结论

是。CRMEB 的 H5 与小程序可由后台页面装修驱动；页面不是固定写死的首页。其核心链路是：

```text
平台/商户 Vben 装修编辑器
  → 保存 {page, items[]} 文档与素材/链接配置
  → 设为首页（同一范围只保留一个启用页）
  → C 端 GET /diy/home 或 GET /diy/pages/:id
  → uni-app x 按组件类型渲染并跳转至业务页
```

平台模板可以供商户复制；商户页必须按 `mer_id` 隔离。素材、页面链接、页面分类、主题配置、页面模板和页面本体都是独立管理对象。

## CRMEB 对照能力

从 CRMEB `route/admin/diy.php`、`route/merchant/diy.php` 与 API DIY 控制器确认的能力：

- 页面装修：列表、详情、新增/编辑、复制、恢复、删除、设为首页。
- 页面类型：首页、微页面、个人中心、店铺街、商品详情、悬浮菜单、商品分类、商户模板。
- 页面资产：图片/视频素材、页面分类、页面链接、商品与营销数据选择。
- 运行时：C 端根据 `diy_id` 和组件参数加载相应商品、营销、店铺、文章、直播等数据；缓存不能成为发布状态的唯一来源。

## 七禧当前实现

### 已实现

- 平台与商户后台使用 Vben 5.7+ 的三栏编辑器：组件库、手机预览、属性设置。
- DIY 配置属于新三库重构范围：统一后台配置使用 `qixi_crm_a_`，店铺装修配置使用 `qixi_crm_m_`；禁止沿用旧 `qixi_m_*` 表。
- 页面跳转不依赖自由输入：统一后台与店铺系统维护各自链接库，店铺装修器仅读取已启用的店铺链接，避免把后台路径写入 C 端页面。
- 首页与微页面分开管理：`is_diy=1` 是同范围唯一启用首页；`is_diy=0` 是独立发布的微页面，可由链接选择器生成 `/pages/diy/page?id={id}` 跳转，不会互相覆盖。
- 设为首页会清除同一 `mer_id + is_diy` 范围的旧启用页，再启用当前页。
- C 端新增运行时渲染入口：`/diy/home`（启用首页）与 `/diy/pages/:id`（已启用指定页面）；草稿不暴露给公共 C 端。
- uni-app x 已渲染首批首页核心组件：轮播/合并头图、导航、标题、公告、单图/橱窗/热区、视频、商品组与主要营销商品组、优惠券、文章/快报、门店、直播、搜索、客服、富文本、辅助空白与辅助线。
- DIY 跳转按客户端类型处理：底部 Tab 使用 `switchTab`，普通 uni-app x 页面使用 `navigateTo`，HTTP(S) 外链通过同一套 uni-app x WebView 页面打开。

### 未完成，不能标记为 100% 对齐

- 平台/商户素材库已使用当前 Vben 页面与 `/attachments` 接口，支持分类、图片/视频上传、删除和 COS 落库；商户素材按 `mer_id` 隔离。
- DIY 编辑器的图片字段与视频组件已接入该素材选择器；页面端可渲染装修视频。其余 CRMEB 组件的数据源、链接类型与样式参数仍须逐组件验收，不能标记为 100% 对齐。
- 主题、个人中心、店铺街、商品详情、悬浮菜单等独立装修页尚未全部迁移为 Vben 页面。
- 所有 CRMEB 组件的业务数据源（文章、店铺、优惠券、直播、秒杀倒计时等）还需逐个接入；未知组件不能默认为已支持。
- 预览链接、草稿/发布版本、发布审计日志及缓存失效策略尚未完整实现。

后续验收必须以 [CRMEB → Vben 后台对齐验收](./crmeb-vben-parity.md) 的逐页标准执行，不能因编辑器存在即判定 DIY 已完成。
